# wood package catalog

This directory holds the research catalog for `wood add owner@package`. It pins each official
package to a SHA-256 checked archive in the 1.1.0 release. See [package setup](../docs/packages.md#catalog-for-the-11-release)
for use with the downloadable compiler.

The catalog stores **metadata only**. Package source stays with its author: on GitHub,
any HTTPS Git host, or a pinned archive at any HTTPS URL. There is no package server to
pay for, and direct installation with `wood add github@owner/repo` never needs a listing.

## Layout

```text
catalog/
  packages/OWNER/NAME.json   One reviewed entry per package
  index.json                 Generated by: wood package catalog build catalog
```

Do not edit `index.json` by hand.

## Entry format

```json
{
  "owner": "john",
  "name": "gui",
  "package": "externalgui",
  "tier": "community",
  "description": "Widgets for desktop applications.",
  "readme": "Optional longer Markdown shown on the package page.",
  "license": "MIT",
  "repository": "https://github.com/john/externalgui",
  "homepage": "https://example.com",
  "docs": "https://example.com/docs",
  "categories": ["desktop"],
  "platforms": ["windows-x86_64"],
  "example": "import gui.widgets as widgets\n",
  "versions": [
    {
      "version": "1.2.0",
      "published": "2026-11-01",
      "dependencies": ["wood@log"],
      "source": {"type": "github", "repo": "john/externalgui", "ref": "v1.2.0", "commit": "FULL_COMMIT_ID"}
    }
  ]
}
```

| Field | Rule |
| --- | --- |
| `owner`, `name` | Must match the file location. Form the identity `owner@name` |
| `package` | The `name` in the package's own `wood.json`; checked by `verify` |
| `tier` | `official` is reserved for the `wood` owner; everyone else is `community` |
| `description` | Required, at most 200 bytes |
| `license`, `repository` | Required; the repository must be plain `https://` |
| `categories` | `audio cli data desktop graphics images math networking system text tooling testing web` |
| `platforms` | `windows-x86_64`, `linux-x86_64` |
| `versions` | At least one. Add `"yanked": true` to hide a version from new installs |
| `recommended` | Optional editorial notes: `note`, `by`, `on`, and optionally `version`. Says nothing about auditing |

A version can also carry two records, normally written by the registry:

| Field | Meaning |
| --- | --- |
| `revoked` | The reason. `wood add` refuses this version, and restoring a project that pins it warns |
| `verification` | One audit of this exact version: `artifact`, `auditor`, `date`, `scope`, `findings`, `limitations`, optionally `commit`. It never carries over to another version, and it is not a guarantee of safety |

Unknown fields are rejected. In particular there is no `audited` or `verified` flag: a listing
is not a security review, and an entry cannot claim to be one without a full audit record.

### Sources

| `type` | Required fields | Optional | Pin |
| --- | --- | --- | --- |
| `github` | `repo`, `commit` | `directory`, `ref` | Full commit ID |
| `git` | `url` (HTTPS), `commit` | `directory`, `ref` | Full commit ID |
| `archive` | `url` (HTTPS), `sha256` | | SHA-256 of a `wood package pack` `.woodpkg` |

Every source is pinned. Tags can move, so `ref` is only informational and is never used
to fetch. `directory` selects a package inside a larger repository.

## Trust rules

- A **community** GitHub entry must be hosted under the account it claims, so `john@gui`
  has to live under `github.com/john`. Custom hosts are judged by reviewers.
- Only the `wood` owner can be `official`, and it can only be `official`.
- `wood package catalog verify` fetches every pinned source and compares its real
  manifest with the listing. CLI installation repeats that comparison.

The chain is: reviewed entry → pinned commit or SHA-256 → the project's `wood.lock`.
Entries are not cryptographically signed. Reviewed pull requests and Git history are the
current trust root, and that limit is documented rather than hidden.

## Submitting a package

```sh
wood package validate
wood package prepare
git tag v1.0.0 && git push origin HEAD v1.0.0
wood package listing --tag v1.0.0
```

Save the printed entry as `packages/OWNER/NAME.json`, fill in the description, license,
categories and platforms, then run:

```sh
wood package catalog validate catalog
wood package catalog verify catalog
```

This catalog takes no submissions now, but a fork that runs its own catalog can keep this process. See
[Publishing packages](../docs/package-publishing.md).
