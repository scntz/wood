# wood 1.1.0

wood 1.1.0 adds to 1.0.0 without breaking it: programs that build with 1.0.0 build and behave the same. It is for Windows
x86-64 and Linux x86-64. The language version is still 0.4.0 and the native runtime is still ABI 4.

## What is new

- **Tuple unpacking.** `q, r = divide(17, 5)`, `a, b = b, a` and `for name, count in pairs:`, with the count checked at
  compile time.
- **Narrowing.** After `if x is not None:`, in the `else` of `if x is None:`, and after an `if x is None:` that returns,
  raises, breaks or continues, `x` has its plain type, so `unwrap` isn't needed there.
- **`finally`, your own error codes and rethrow.** A `finally:` block runs however the `try` statement is left.
  `raise error("app.not_found", "message")` raises an error with your program's own code, and a bare `raise` in an
  `except` block passes the error on. See [errors](../errors.md).
- **Character functions.** `char_count`, `chars` and `char_slice` work on UTF-8 characters. `str`, `len` and indexing
  still work on bytes.
- **`wood fmt`.** Formats `.wd` files in one layout, and `--check` lists the files that would change. It refuses any
  result that would lex differently, so it can't change what a program does. The language server and the VS Code
  extension format documents the same way. See the [command-line reference](../cli.md).
- **Faster loops over lists and arrays.** Indexing checks bounds and copy-on-write ownership inline, so loops that read
  and update lists and arrays run 2 to 13 times faster. N-body went from 2356 to 178 ms. Dictionary-heavy loops are
  unchanged. See [performance](../performance.md).

## Upgrading

Install 1.1.0 over 1.0.0 the same way. `finally`, `chars`, `char_count` and `char_slice` are not reserved words, so
existing variables and functions with those names keep working. `wood.lock` files record the language version, 0.4.0,
so they stay valid.

## Known limits

The [known limitations](../known-limitations.md) of 1.0.0 still apply: Windows files are not code signed, a clean machine
has not been tested, macOS is not supported, and TLS and HTTPS need OpenSSL 3 installed separately.
